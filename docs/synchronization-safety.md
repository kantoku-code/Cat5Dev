# 同期処理の保護と復旧

Pull は、取得結果をすべて検証してからローカルの `modules/` に反映します。上書きの確認はありません。CATIA 側に存在しないローカルモジュールを削除する場合だけ確認します。「残す」を選ぶと、そのファイルを残して上書き・追加を続けます。ダイアログを閉じると Pull 全体をキャンセルします。

反映対象に未保存の編集がある場合や、取得中にローカルモジュールが変更された場合は反映を中止します。反映に失敗すると退避した内容から復元します。復元にも失敗した場合はワークスペース内の `.cat5dev-pull-*` に退避と `recovery.json` を残し、通知に復旧先を表示します。このフォルダは復元するまで削除しないでください。

`C5D_` で始まるモジュールも利用者の通常のモジュールとして扱います。プロジェクト一覧取得や Pull、Push の事前確認で、自動的に削除することはありません。明示的な Push の削除同期は、選択したプロジェクトに限定されます。

CATIA 操作は、同じユーザーの別ウィンドウ・別ワークスペースを含めて同時に1件だけ実行できます。操作ごとに独立した一時フォルダを使います。実行中に次の操作を要求すると通知して受け付けません。

CATIA の完了を60秒以内に確認できない場合、成功とは通知せず、ロックと一時データを保持します。`cscript.exe` の終了だけでは CATIA 内部処理の終了を保証できないため、自動的な再実行はしません。後から正しい完了結果を受信するとロックを解放します。

終了が確認できないままの場合は、CATIA 側の状態を確認して必要な内容を保存し、CATIA を終了してください。その後 VSCode のウィンドウを再読み込みし、コマンドパレットの **CATIA: Recover Synchronization Lock / 同期ロックを復旧** を実行します。実行元が生存している、CATIA が稼働中、または状態確認に失敗した場合は強制解除しません。異常終了時の診断データは復旧後も保持します。

Push の一部失敗は成功件数と失敗件数を通知します。既に反映された CATIA 側の変更を自動的に巻き戻す機能はありません。詳細は「CATIA VBA Sync」の Output を確認してください。Push 後の CATIA 側での保存は引き続き必要です。

検証コマンド:

```text
npm run test:unit
cd tools/vbafmt
go test ./...
```

`test:unit` は Node 標準のテストランナーを使用します。生成したスクリプトの実行テストでは、Windows の WSH と ADODB を使い、CATIA のオブジェクトだけを模擬します。利用者の CATIA プロジェクトを変更するテストではありません。
