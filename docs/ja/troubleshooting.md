# トラブルシューティング

[← README に戻る](README.ja.md)

## まず確認すること：出力パネル

エラーの詳細は VSCode の出力パネル（メニューの「表示」→「出力」、または `Ctrl+Shift+U`）に記録されます。右上のドロップダウンで次を選んでください。

| 出力チャンネル | 内容 |
|----------------|------|
| **CATIA VBA Sync** | CATIA との通信（プロジェクト選択・Pull・Push）、Lint・フォーマッタの記録。エラー時は自動で開きます |
| **VBA Language Server** | 補完・ホバーなどを行う言語サーバーの記録 |

---

## ツリーに何も表示されない

- **対象プロジェクトが未設定です。** ⚙️ ボタンでプロジェクトを選んでください。
- **`cat5dev.toml` がありません。** `cat5dev.toml` が無いと、選んだプロジェクトが保存されず、ツリーは空のままです。コマンドパレットから `CATIA: Initialize Project (cat5dev.toml)` を実行してから、もう一度 ⚙️ でプロジェクトを選んでください。
- **`modules/` にファイルがありません。** ☁️↓ で Pull してください。

## CATIA に接続できない（Pull / Push / プロジェクト選択が失敗する）

- 「CATIA が起動していません。CATIA を起動してから再実行してください。」と表示された場合は、CATIA V5 を起動してから再実行してください。
- 「CATIA の VBA エディタ（Alt+F11）を一度開いてから再実行してください。」と表示された場合は、CATIA で VBA エディタを一度開いてから再実行してください（閉じた後でもかまいません）。VBA エディタを開くまで、Cat5Dev からは VBA プロジェクトが見えません。
- 対象の VBA プロジェクトが CATIA で開かれているか確認してください。開かれていない場合は「Target project not found」と記録されます。
- `cat5dev.toml` の `target_project` が CATIA 上のプロジェクト名と一致しているか確認してください（大文字と小文字を区別します）。
- 詳しくは出力パネルの「CATIA VBA Sync」を確認してください。

## 「Cat5Dev の仲介プロジェクト（C5D_Bridge）を準備できませんでした」と表示される

Cat5Dev が CATIA に読み込む仲介用のプロジェクト `C5D_Bridge` を準備できなかった状態です（[仕組み](sync.md#catia-とのやり取りの仕組み)）。このとき、利用者の VBA プロジェクトには何も書き込んでいません。

1. 出力パネルの「CATIA VBA Sync」で詳細を確認してください。
2. CATIA でダイアログ（MsgBox など）が開いていれば閉じて、少し待ってから再実行してください。直前の処理が終わっていないと、このエラーになることがあります。
3. `%LOCALAPPDATA%\Cat5Dev\bridge\` に書き込めるか確認してください（権限、ウイルス対策ソフトなど）。
4. 解決しない場合は、CATIA で必要な作業を保存してから CATIA を再起動し、再実行してください。

## VBA エディタに `C5D_Bridge` というプロジェクトが表示される

Cat5Dev が処理中に一時的に読み込む仲介用のプロジェクトです。処理が終わると外れます。読み取り専用で、保存はされません。編集や保存はせず、そのままにしてください。

処理がタイムアウトした場合などで処理の後も残っていることがありますが、次のプロジェクト選択・Pull・Push のときに自動で外れます。CATIA を終了しても消えます。

## 「別の CATIA 操作が実行中…」「完了を確認できません」と表示される

CATIA との通信は同時に 1 つしか実行できません。他の VSCode ウィンドウで Pull / Push を実行していないか確認してください。

処理が 60 秒以内に終わらなかった場合は、二重書き込みを防ぐためロックがかかったままになります。[同期ロックの復旧手順](sync.md#完了を確認できませんと表示されたとき) に従ってください。

## Pull が「未保存の編集…」で中止される

`modules/` 内に未保存のファイルがあると Pull は実行されません。`Ctrl+K S`（すべて保存）で保存してから再実行してください。

## Pull に失敗して `.cat5dev-pull-XXXXXX` フォルダが残った

Pull の途中で失敗し、元に戻す処理も完了しなかった状態です。エラーメッセージに表示されたフォルダの `backup/` に元のファイルがあります。`modules/` に復元してから、このフォルダを削除してください。

## Push したのに CATIA に反映されていない／CATIA を再起動したら消えた

Push は CATIA のメモリ上に書き込むだけです。**CATIA の VBA エディタでプロジェクトを保存**してください。

## ユーザーフォームを Push できない

CATIA に同じ名前のユーザーフォームが無い場合は作成できず、スキップされます。CATIA の VBA エディタで同じ名前の空のユーザーフォームを作ってから Push してください。

## 文字化けする

Pull / Push は本文を Unicode のまま運ぶため、日本語など Windows のシステムの ANSI コードページ（日本語版 Windows では Shift-JIS）で表せる文字は化けません。絵文字（例：`🙂`）など ANSI コードページで表せない文字は、VBA がモジュールに保存する時点で `?` に置き換わります。これは VBA の仕様で、VBA エディタに直接入力した場合と同じため、避けられません。`cat5dev.toml` の `encoding` は使われなくなりました（残っていても無視されます）。以前の版で Pull したファイルが化けている場合は、もう一度 Pull してください。[文字コード](sync.md#文字コードエンコーディング) を参照してください。

## Lint の波線が出ない／フォーマッタが動かない

- `cat5dev.toml` で `[lint] enabled = true`、`[formatter] enabled = true` になっているか確認してください（既定はどちらも `false` です）。
- ファイルの拡張子が `.bas_utf` / `.cls_utf` / `.frm_utf` か確認してください。
- 出力パネルの「CATIA VBA Sync」にエラーが無いか確認してください。

## 保存するたびにコードが書き換わる

`[formatter] enabled = true` のときに、次のどちらかで保存時に整形されます。不要なら両方を無効にしてください。

- `cat5dev.toml` の `format_on_save = true`
- VSCode の設定 `editor.formatOnSave` が有効（`format_on_save` に関係なく整形されます）

## 補完やホバーが表示されない

- `As Object` / `As Variant` の変数には補完が出ません。型を宣言するか、[型ヒント `'@As`](intellisense.md#型ヒント-as) を付けてください。
- `CATIA.ActiveDocument.` で `PartDocument` のメンバーが出ないのは仕様です。`Dim oDoc As PartDocument` と宣言してください。
- 他のモジュールのプロシージャが出ない場合は、そのファイルが `modules/` 直下にあるか確認してください（サブフォルダは対象外です）。
- 出力パネルの「VBA Language Server」にエラーが無いか確認してください。

## CATIA の型に説明文が表示されない

同梱の型情報には説明文が含まれていません。[説明文付きのデータベース](intellisense.md#説明文を表示したい場合) を作成して設定してください。
